# 后续提交版接入清单

**现在交付的是本地版。** `STARHALL_MODE=cloud` 会明确报错，防止未接入就误报上线。用户另行声明制作提交版后，再进行以下工作。

## 真实模型

需要提供服务商、可用模型ID、API地址与密钥。已有两类模型协议适配器及替身测试。接入后验证：认证、JSON结构、所有服务的内容质量、五回合谈判、中文长度、实际价格/配额约束、生成耗时和超时策略。

密钥放本机 `.env`，不要写进产品说明、作品、提示词或审计日志。三位明星共享配置，账本不调用模型。

## SharedOS Cloud / SharedNet

需要官方提供的 tenant ID、owner address、托管服务地址及认证机制，另需明确 SharedNet 挂牌、发现、计价与支付协议。当前本地身份 ID 不能直接当成云端节点地址。

1. 核对当时 SDK / 云端协议兼容版本，再锁定版本。当前固定 alpha.5；不得臆测云端 API 路径。
2. 注册三个明星和账本的四个独立节点，接入已有经纪人的参赛节点。
3. 将接收 turn 真正迁入托管内核，配置每个身份的 grants 和可信上下文。仅从本机发送一个日志请求不能满足“托管执行”。
4. 将本地入口权限映射为平台服务授权与独立接收 turn，核对 broker、明星、账本之间的边界和 escalation 语义。
5. 替换本地模拟余额为真实支付/扣分回执的校验流程，设计真实回执的幂等、失败补偿和结算策略。不得相信买家自报已付款。
6. 使用目录里的标价、输入及输出结构挂牌服务。免费榜和会员墙分别暴露受控入口。
7. 接入真实外部市场 transport、经纪人点评、排名和采购。增加持久化进度恢复、真实回执对账和失败重试，不能拿 fixture 演练报告提交。
8. 验证两条成功调用链和两条故意拒绝链，并确认所有记录能在组织者可见的托管审计中找到。

提交用核心 purposes：`arena-demo`、`market-tip`、`ledger-update`、`escalation-review`。本地另外使用 `summary` 和 `full-wall` 区分账本读取，云端映射时保留各自边界。

## 比赛材料

本地项目没有执行：注册报名、发 Discord 消息、发房间消息、购买外部产品、提交排名、创建公开仓库、上传或发布 Devpost 页面。

后续以用户指定的提交版为范围，补齐真实节点地址、服务调用地址、仓库链接、队长信息和必要的演示材料，并按官方最终赛程校对时区。

参考：[SharedOS 官方 Quickstart](https://www.sharedos.ai/docs/quickstart)、[SharedOS SDK 源码](https://github.com/Aicoo-Team/SharedOS)。本地构建时也直接核对了安装包中的接口与执行行为。
