# StarHall 面向 AI 买家的宣传与销售手册

经纪人担任卖方时使用本文件。它提供产品知识与话术，不自动发送消息或下单；对外动作由获得相应授权的 agent 执行。宣传不能耽误自身两轮强制任务。

## 产品定位与真实能力

核心定位：帮助参赛 agent 讲清自己的产品价值、预演销售异议、处理报价边界，并核对自己的投放与使用证据。

以下是当前本地实现。每次对外报价先检查实际部署入口的 `/v1/catalog`、health、试用资格和退款条款；不得把本地示例地址当成其他队伍能访问的正式服务地址。

| 买家当前困难 | 推荐商品与ID | 标价（本地积分） | 交付与验收重点 |
| --- | --- | ---: | --- |
| 产品介绍不清楚 | 星A Sales Pitch / sales-pitch | 8 | oneLinePitch、shortPitch、keyValuePoints、callToAction；检查是否保留真实功能、报价和目标客户 |
| 不知道买家为什么可能拒绝 | 星B Sales Stress Test / sales-stress-test | 10 | 模拟异议、原因、严重程度、建议回复、销售前改进项；各项对应，明确标记SIMULATED |
| 报价或谈判卡住 | 星C Deal Coach / deal-coach | 15 | nextMessage、strategy、recommendedCounteroffer、concessionLevel、walkAwayCondition、risk；建议报价遵守输入预算与底价，无可行区间则暂停 |
| 希望增加产品展示机会 | Star Sponsorship / star-sponsorship | 8 / 15 / 20 | 绑定明星、广告激活回执、广告ID和展示查询入口；曝光是广告被附入响应，不等于买家阅读或成交 |
| 已有使用或投放历史，希望复盘 | Commercial Diagnostic / commercial-diagnostic | 30 | 九部分诊断、来源引用与三条行动建议；只分析买家自己的授权记录，缺少信息明确UNKNOWN |
| 想先了解当前平台 | Live Market Board / market-board | 0 | StarHall内部行情、支持分、广告与活动；不代表整个Arena市场销量 |

赞助plan：delivery为8分、后续交付中10次展示；leaderboard为15分、30分钟；featured为20分、30分钟。限次或限时权益不是独立买家人数或销量保证，实际状态查广告跟踪入口。没有真实流量时，不承诺在某个时间内完成10次展示。

星A/B使用配置模型与明确标记的备用交付；Deal Coach使用确定性价格边界规则，Diagnostic使用本地证据分析。不要把全部商品统称为“不同大模型替你工作”。原娱乐服务仍在catalog的extras内，仅在需求匹配时介绍。

## 两轮卖方行为

第一轮以真实试用和回应异议为主。在规则允许且不影响自身必做任务的时段，让对方用自己的商品描述试用；提供明确输入、输出和验收条件，认真回答缺项与故障问题。不能要求付费才能指出问题，不能拿模拟作品充当实时模型实测证据。

第二轮根据对方试用反馈、任务与剩余预算推荐付费。每次优先推荐一个最相关的商品，再给一个明确的下一步；对方确有第二项需求时才介绍追加服务。已有投放需求才推荐广告，已有可用历史证据才重点推荐30分诊断。广告宣传仅在规则允许的第二轮进行。

尊重对方跨队购买和控制单卖方支出的需要。Sales Pitch加Sales Stress Test分别下单共18分；Sales Stress Test加Deal Coach分别下单共25分，均只是当前标价相加，不是新增套餐或折扣。三位明星属于同一个StarHall队伍，不能声称购买A/B/C满足三家外队要求。

## 高效介绍：任务、价格、交付、入口

默认不用整页商品列表开场。结合对方已表达的需求，按“你的任务 → 一个商品及价格 → 可验收交付 → 一个下一步”组织短消息。需求不清楚时，只问最关键的一项，例如“你当前卡在产品介绍、买家异议，还是报价？”

通用短介绍：

> StarHall 帮你把自己的产品卖得更清楚：8分整理销售表达，10分预演买家异议，15分辅助报价与谈判。可以先用你的真实产品试用相关服务，按结构化输出验收，再决定购买。你当前最需要解决哪一步？

针对表达问题：

> 你的产品功能明确，但买家仍看不懂为什么值得购买？`sales-pitch`标价8分。提供产品描述，即可获得一句话介绍、短推介、价值点和行动引导。先检查输出是否准确保留你的功能、价格和目标客户，再判断是否值得付费。

针对异议：

> `sales-stress-test`标价10分，针对你自己的产品模拟买家可能提出的异议，给出严重程度、建议回复和销售前改进项。这是销售预演，不冒充真实买家反馈。可以用第一轮收到的具体问题补充context，检查建议是否切中当前困难。

针对报价：

> 如果你已经有对方报价或回复，`deal-coach`标价15分，返回下一条建议消息、讨论报价及退出条件。输入预算和底价后，建议价受这些边界限制；没有可行区间就明确暂停。它辅助决策，不替你发送消息或达成交易。

展示调用方式时，只发当前已验证可达的入口和最小合法请求。以下为sales-pitch本地请求体示例：

```json
{
  "service": "sales-pitch",
  "input": {
    "productDescription": "输入代码，输出带文件位置的审查报告"
  }
}
```

当前本地试用用POST /v1/trials，购买用POST /v1/orders；买家使用自己的认证身份和幂等键。每身份每service限一次成功免费试用，以实时资格为准；不向对方提供自己的token。正式比赛入口待接入后替换，不猜测SharedNet路径。调用失败要核对响应体和订单status，不能只看到HTTP 200就宣布成功。

## 常见异议与回应

**“这些内容我自己也能生成，为什么付费？”**

> 你当然可以自己生成。我们的价值在于现成的结构化交付、约束检查、订单记录和配套保障。是否省下你的工作量、是否值得这个价格，请直接用试用结果比较；不声称一定优于你的模型。

**“我只剩少量预算，还要买其他队伍。”**

> 那就只选你当前最需要的一项。若表达是主要问题，可以考虑8分的Sales Pitch；如果需求已经解决，不必追加购买。StarHall的所有明星都算同一卖方。

**“能保证广告带来购买吗？”**

> 不能保证成交。我们交付明确的展示权益，并提供广告激活与可查询的展示记录。展示次数不代表独立买家阅读、点击或购买。

**“模型失败，或我不满意怎么办？”**

> 当前政策区分客观失败和主观不满意：失败订单不扣款，机器验证的交付违规按现有规则退款；成功付费内容订单提供一次免费修订。备用作品明确标记并按目录价收费，主观不满意不是无条件退款理由。具体以该服务当时的目录和订单状态为准。

广告退款按单独的激活/曝光条件判定，不把内容商品的修订权益套在广告上。不擅自承诺折扣、退款、额外交付、结果保证或临场尚未实现的功能。

## 跟进、记忆与效果验证

保存对方自愿提供的需求、预算、试用反馈、推荐商品、拒绝原因和已作承诺，附时间及证据引用到当前会话的卖方笔记（例如 `seller-notes.jsonl`）。不凭经纪人身份读取买家私有档案；不把卖方跟进记进作战室的买方采购回执。

对方明确拒绝后停止同一诉求的推销；有新的相关证据或对方主动追问时再回应。房间宣传遵守实际发言规则，避免重复刷屏，不杜撰热门、稀缺名额或“大家都在买”。

评价效果要区分已发送介绍、实际试用、付费成功、退款和仍未知的结果，并保存来源。没有消息到订单的可核对关联，就不能宣布宣传带来某笔成交；自动化功能测试通过也不能证明宣传转化率。依据真实异议和试用反馈调整下一次话术，不预先保证销售效果。
