# 0.2.0 历史修复记录（以下为当时结果）

日期：2026-09-10（北京时间）。本次范围是本地产品可靠性与买家回归，不是云端参赛提交。

## 复现与根因

用真实 DeepSeek V4 Pro 复现了一次失败的 review：服务端收到 HTTP 200，模型也输出了完整评审，但结构是 `review.sections`，同一响应还生成了 negotiate 和 tactics 两份无关内容。旧提示词混合介绍所有服务的格式、只给通用 title/text 示例，且模型请求未显式携带本次服务ID；旧校验只接受顶层 sections。这同时造成多生成、延迟和错误拒收。原始响应保留在 `artifacts/model-diagnosis.json`，其中没有请求认证头或密钥。

另一个独立原因是 `.env` 中 `LLM_FALLBACK=false`。这是最初验证API连接时的诊断设置，后来没有恢复，导致结构校验错误直接变成失败订单。现在已开启true，保留原有密钥及其他模型设置。

存档中确实存在失败单，原始 `GET /v1/orders` 实现也没有过滤失败状态，不能根据某次客户端只看到成功单就断言存储丢单。本次增加完整HTTP回归、显式状态过滤、按幂等键查询与服务版本/数据集标记，帮助排查旧进程或用错买家/数据目录的问题。

## 实际修改

| 问题 | 处理 |
| --- | --- |
| 星B/C结构错误 | 每项服务单独完整JSON示例；请求显式带service；解包当前服务，不接受无关服务结果 |
| 格式差异 | 支持review章节map、数值字符串回合编号、对象形式话术；缺少完整五回合时拒收，不伪造缺失内容 |
| 结构错误直接失败 | 本地归一化后最多一次有时限的修复，仍失败时按配置交付完整备用作品 |
| 失败等待 | 首次生成最多25秒、修复最多20秒，合计不超过45秒；网络/认证错误不重复请求 |
| 目录不透明 | 展示fallback策略与最近20单live/fallback/mock/failed统计；没有真实样本时明确unverified |
| 评审/吐槽跑题 | 不向模型传入历史购买主题；按当前产品限定对象；内部提示内容泄漏会触发修复。问候仍保留粉丝记忆 |
| 空输入预测单薄 | 提供积分API市场的评分尺、核验问题、预算及止损建议，不编造冠军；校验100/80积分语境 |
| 套餐立场不反转 | 星A收到独立stance=defend、原产品及critique，以产品方第一人称回应 |
| 卖方话术矛盾 | 要求单一条件交换；补充原修订次数与买卖方立场校验，不能把未提供的标准次数当事实 |
| 失败响应丢诊断 | 终态订单统一HTTP 200，以status区分delivered/failed；失败含charged=0、fundsReleased、耗时和查询地址 |
| 幂等冲突难恢复 | 409指出不一致字段及原单地址；GET /v1/orders/by-key无需重建原正文 |
| 空白留言 | 保留原message，另加带system来源的displayMessage，不伪造买家原话 |
| 社交证明少 | 展示20条真实历史、总笔数与积分；未发生金主购买时不造置顶感谢 |
| 初始账户不干净 | sandbox和买家回归每次创建独立目录、三个100分账户，日常data不变 |
| 缺少跨队练习入口 | 独立测试服务提供四家明确标记的模拟竞品及试用、排名、采购、钱包接口；真实竞品仍未连接 |

备用作品始终标记 `generation.mode: fallback` 并按目录价收费。严禁把fallback记成真实模型成功；若不接受备用作品，可关闭fallback，失败订单不会扣分。上墙、积分与记忆仍同一事务提交，幂等查询不会重复扣款。
